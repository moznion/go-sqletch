# sqletch Design — 12: v1.0 (stability audit and documentation plan)

v1.0 per PROJECT_INSTRUCTION: **stable template language and generated
API; comprehensive documentation; sqlc coexistence/migration guide.**
Breaking changes are free until the v1.0.0 tag and expensive after —
this doc records the pre-freeze audit of every surface v1.0 pins, the
fixes made, and the documentation plan.

## 1. Audited surfaces and verdicts

| Surface | Verdict |
| --- | --- |
| Template language (constructs, `-- name:` headers, `-- @param` / `-- @column`) | **Freeze as-is.** Construct vocabulary survived four milestones without a rename; annotations are uniform across dialects. |
| Generated API (`New(DBTX)`, `Queries`, `WithTx`, `OnQuery`, `Querier`, params/rows structs, per-query enums/constructors) | **Freeze as-is.** Deliberately sqlc-shaped; both driver flavors (pgx, database/sql) mirror sqlc's, so coexistence stays trivial. |
| `runtime` package | **Freeze, with the contract written down** (package doc "API contract (v1)"): user API (Tree, caps, sentinel errors) vs generated-code contract (Frag/ShapeKey/…, public only because generated code lives outside the module; regenerate after upgrading sqletch). Considered splitting machinery into a subpackage; rejected — churn without a compatibility gain, and the doc contract covers it. |
| `sqletch.yaml` | **Freeze as-is.** Keys reviewed; naming consistent (`static_expansion`, `filter_tree_caps`, `database.dsn` with per-dialect meaning). Strict decoding already rejects unknown keys. |
| CLI (`generate` / `check [--exhaustive]` / `explain [--enumerate|--analyze]` / `fmt [--check]` / `lsp` / `version`, `--config`, `--json`, exit codes 0/1/2) | **Freeze as-is**; exit codes documented in the manual. |
| Diagnostics | **Freeze code MEANINGS, not message text.** 40 codes, no collisions. The manual gets a reference table with a test asserting every constant is documented (drift-proof). |
| Committed cache format | **Fixed pre-freeze**: files now carry `"format": 1` (`cache.FormatVersion`); any other value — including its absence in pre-1.0 caches — loads as a miss, so format evolution can never misread an old entry, it just re-describes. One-time invalidation of pre-1.0 caches (examples cache regenerated). |
| Go module versioning | Single module `github.com/moznion/sqletch`; tag `v1.0.0` keeps import paths stable. `sqletch version` exists for release identification. |

## 2. Compatibility promises at v1.0 (the short list)

1. Template language: constructs and directives keep meaning; new
   constructs may be added (old templates never change behavior).
2. Generated API: regenerating with a newer v1 sqletch may add
   surface but does not break compiling callers, except where a
   template change forces it.
3. `runtime`: Go API compatibility for all of v1; regenerate after
   upgrading sqletch (conformance is per version pair).
4. Diagnostics: codes are stable identifiers; message wording is not.
5. Cache: self-describing format; unknown formats degrade to
   re-describe, never to misreads. The cache remains an offline
   optimization — deleting it is always safe.
6. `sqletch.yaml`: existing keys keep meaning; unknown keys stay
   errors.

## 3. Documentation plan (phase 2)

User-facing manual under `docs/manual/`, written against the shipped
behavior (examples lifted from the test corpora so they are known to
compile):

- `01-getting-started.md` — install, sqletch.yaml, first template,
  generate/check loop, committed cache in CI.
- `02-template-language.md` — reference for every construct with the
  rules (R1–R9) stated as user-facing constraints, anchors, slots.
- `03-annotations.md` — `-- @param` / `-- @column` per tier.
- `04-dialects.md` — per-dialect specifics: PG (GENERIC_PLAN, 16+),
  MySQL (mandatory annotations, EXPLAIN plan check, TiDB-parser
  limits), SQLite (no-Docker oracle, decltype/affinity, rqlite/sql
  limits, quoting keywords like `ACTION`).
- `05-config.md` — sqletch.yaml reference.
- `06-cli.md` — commands, flags, exit codes, `--json` diagnostics.
- `07-runtime-and-generated-code.md` — generated API tour, filter
  trees across layers, caches, static expansion.
- `08-diagnostics.md` — the SQLETCHnnn reference table
  (coverage-tested).
- `09-editors.md` — LSP + grammars.
- `10-sqlc-migration.md` — coexistence and migration guide.
- `examples/` grows MySQL and SQLite variants of the showcase.

Release engineering (tag, CHANGELOG) happens after the docs land.
